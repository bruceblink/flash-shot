# Bug 修复与 UI 打磨开发计划

更新日期：2026-08-27
源代码基线：`f801e28`、应用版本 `0.1.2`
计划状态：执行中

本文档把 [下一阶段开发计划](plan.md) 中的可靠性、可维护性、信息架构、视觉系统和国际化工作拆成可执行
切片。它是执行清单，不替代产品需求、架构文档或 [开发流程与验收证据](development-workflow.md)。
每个切片都必须先明确边界，再开发、验证、提交和推送。

## 1. 目标与范围

### 1.1 本阶段目标

1. 让截图核心链路在失败、取消、重复触发和异步结果晚到时保持可恢复：触发、选区、标注、复制、保存、
   Pin、历史、清理都不能把应用留在永久忙碌或不可再次截图的状态。
2. 对水印、文字和箭头等高风险标注路径建立回归保护，避免再次出现进程崩溃、缓冲区越界、导出异常或
   第二个箭头方向错位。
3. 完成 Capture、Library、Record、App、Pin 的信息层级收敛，统一主次操作、状态反馈、焦点态和控件命中区。
4. 把 Record、OCR、更新、错误、忙状态和动态数量等剩余用户可见文案迁移到应用自己的 `Locale`/`UiText`
   资源；OCR 保持可选，不能阻塞截图启动和主流程。

### 1.2 明确不在当前交付范围

- 真实 HTTPS 翻译端点的成功、失败和重试闭环；
- 负坐标双屏和混合 DPI 双屏验收；
- 新的标注工具、OCR 引擎、翻译供应商或录屏后端；
- 为追求视觉变化而进行的大规模 GPUI 主线升级或全量重写；
- Linux/macOS 功能对等。

以上事项保留在 [下一阶段开发计划](plan.md) 的暂缓项中，不作为本阶段核心截图发布的阻塞条件。

## 3. 执行规则

每个切片开始前，在提交说明或对应工作记录中写清楚以下内容：

- **目标**：用户能看到或验证的一个结果；
- **非目标**：本切片明确不改的行为；
- **文件边界**：负责的 crate、模块、脚本和文档；
- **前置条件**：需要的 fixture、依赖、显示器/DPI 或可丢弃 Windows 会话；
- **验收证据**：测试命令、Release 原生步骤、报告、截图和像素结果；
- **失败行为**：超时、依赖缺失、权限错误或异步取消后如何恢复。

开发顺序固定为“设计/边界 -> 实现 -> 风险匹配验证 -> 单一 Conventional Commit -> 推送”。一个切片只使用
一个主要提交；行为修复、视觉调整、结构重构、依赖升级和文档变更不得混成一个提交。测试失败、证据不足或
只完成一半的切片留在计划中，不标记为完成。

## 3.5 UI 重设计基线

本节是后续 UI 实现的设计约定。U0 只冻结视觉语言和验收样张，不修改截图像素、快捷键、状态机或窗口
生命周期；后续页面必须复用这些约定，不能重新发明一套颜色或按钮层级。

### 3.5.1 视觉定位

Flash Shot 的 UI 定位为“桌面级视觉创作工具”，科技感来自精确的层级、清晰的状态和可靠的操作反馈，
不是来自装饰。整体应让用户第一眼看到当前截图工作区和下一步动作，设置与诊断退居次级。

- **深色基底**：石墨黑背景、稍亮的工作表面、清晰但克制的细边界；
- **主色**：电光青只用于当前选中、主要动作、焦点和关键测量反馈；
- **状态色**：成功使用绿色、需要等待或注意使用琥珀、失败使用红色；状态色不同时承担普通装饰；
- **材质**：使用不透明或高不透明度表面、细边框和轻微层级差，不使用大面积渐变、玻璃拟态、光晕、
  纹理背景或独立装饰图形；
- **密度**：工具栏和设置页保持紧凑，但每个图标按钮保留稳定命中区；内容边界和状态栏不能互相遮挡；
- **浅色主题**：采用冷白表面和深色文字，保留同一套语义色和层级，不把深色主题简单反相。

### 3.5.2 语义 token

U0 将现有 `ThemeColors` 从“背景/面板/边框/文字/强调色”扩展为语义 token。名称必须表达用途，
不能在页面中直接写颜色值。

| token 组 | 规划用途 | 设计要求 |
| --- | --- | --- |
| Surface | `canvas`、`surface`、`surface_elevated`、`surface_hover` | 三层表面有可感知但克制的明度差，避免每个区域都变成卡片 |
| Content | `text`、`text_muted`、`text_disabled` | 中文/英文均满足正文对比度；禁用态仍能识别控件边界 |
| Action | `accent`、`accent_hover`、`accent_pressed`、`focus` | 主动作明显但不刺眼；焦点环不能依赖鼠标 hover |
| Status | `success`、`warning`、`danger`、`info` | 状态颜色只表达状态；错误反馈同时提供文字和下一步动作 |
| Geometry | `space_1/2/3/4`、`control_height`、`toolbar_height`、`radius_sm/md` | 以 4px 基线组织间距，圆角不超过 8px，固定控件尺寸不因文案改变 |

实现时优先复用 GPUI 的现有布局 API；只有多个页面都需要相同规则时才增加通用 helper，避免新增一层
抽象包裹单个按钮。

### 3.5.3 页面和工具栏层级

| 表面 | 第一眼内容 | 主要动作 | 次级内容 |
| --- | --- | --- | --- |
| App 壳层 | 当前页、Capture 状态、全局语言/主题入口 | Capture | Library、Record、App 设置 |
| Capture 覆盖层 | 选区、尺寸、当前标注工具 | Copy、Save、Pin、Cancel | More、OCR、滚动截图、录屏 |
| Library | 最近截图和筛选结果 | Open/Save | 批量删除、目录、筛选 |
| Record | 目标和当前录制状态 | Record/Stop | Pause/Resume、支持检查、目录 |
| Pin | 当前图片和轻量工具栏 | Copy、Save、Close | Zoom、Opacity、Solo、Mouse-through |

每个区域最多一个视觉最强的主要动作。复制、保存、关闭、缩放等熟悉动作优先使用图标加 tooltip；只有
文字本身能减少歧义时才使用长文本按钮。More 菜单只收纳低频动作，不把错误、忙状态或关键恢复动作藏进去。

### 3.5.4 UI 重设计分批

U0 之后按以下顺序实施，每组独立提交和验收：

1. **App 壳层**：重做标题栏、页面导航、全局状态栏和 Capture 主入口；保留现有四个页面和快捷键；
2. **Capture 覆盖层**：重做选区 HUD、尺寸标签、主操作条、More 菜单和标注工具条；保证工具条在选区边缘
   自动避让，不遮挡标注和截图内容；
3. **Library/Record**：统一内容列宽、列表/状态分组、空状态、忙状态、错误恢复和批量操作；
4. **Pin**：统一轻量工具栏、状态通知、tooltip、窗口边缘间距和关闭反馈；
5. **双语视觉回归**：在 English/简体中文、浅色/深色、420x420/520x640/980x760 逐页复核，记录所有
   文案变长、按钮溢出、焦点丢失和状态遮挡问题。

### 3.5.5 设计验收条件

U0 设计基线完成前，必须保留一组“当前版本 vs 新基线”的对照截图和 token 表。后续 UI 切片只有同时满足
以下条件才算完成：

- 首屏能识别当前页面和唯一主要动作，不需要先读说明文字；
- 主要、次要、破坏性、禁用和忙状态在五个表面中有一致的视觉规则；
- 420x420 窄窗不截断主要动作，520x640 能完整展示核心工作区，980x760 不出现空旷失衡；
- English 和简体中文的最长按钮/状态文案不溢出，文本不会覆盖前后控件；
- 键盘焦点、hover、pressed、disabled、busy、error、success 六种状态都可区分；
- UI 截图只证明布局与视觉，截图像素、导出文件、快捷键和清理状态仍按原生验收报告单独核对；
- 任何“科技感”改动都不得引入渐变背景、装饰性光晕、不可点击的伪控件或仅用于截图的分支。

## 5. Bug 修复主线

### B0：回归基线与问题登记

**负责组件**：`crates/flash-shot-app/src/app/workflow.rs`、`workflow/recognition.rs`、`i18n.rs`、相关
验收 runner。

**动作**：

- 记录当前主线的 Capture -> 标注 -> Copy/Save/Pin -> 清理流程，以及水印、文字、箭头的最小复现输入；
- 枚举用户可见状态、按钮和错误来源，标记已使用 `UiText` 与仍直接写入 `self.status` 的路径；
- 固定每个回归场景的输入尺寸、选区坐标、语言、主题、构建 profile 和输出目录；
- 只补测试夹具、场景说明和稳定 ID，不在本切片顺手修改业务行为。

**完成证据**：静态检查通过；每个场景都有最小输入、预期状态、失败后恢复动作和报告目录；未能稳定复现的
问题登记为“待确认”，不写成已修复。

**失败处理**：如果同一场景在相同构建和输入下结果不稳定，先扩大报告中的状态/清理字段，暂停后续
重构，不用重试次数掩盖问题。

**完成记录（2026-08-26，源代码基线 `f801e28`）**：

- 新增 [Bug 与可见文案基线](bug-ui-baseline.md)，登记截图主链、文字/水印、双箭头、4K 合成、OCR 可选重试、
  重复 Capture 清理和状态文案盘点的稳定 ID、最小输入、预期结果、失败恢复动作与证据位置。
- 新增 `scripts/verify-bug-ui-baseline.ps1` 与 `scripts/test-verify-bug-ui-baseline.ps1`，可在 Windows PowerShell 5.1
  下检查基线 ID、开发工具入口、重复生成和仓库外输出拒绝，
  扫描 workflow 的直接状态赋值与 `UiText` 引用，并生成不包含截图原文或外部响应的 JSON 报告。
- 脚本验证报告记录 7 个场景、317 个直接 `self.status` 赋值和 34 个 `UiText` 引用；这些数量用于后续 U1
  迁移对照，不代表尚未执行的原生交互已经通过。

### B1：主流程故障恢复

**负责组件**：剪贴板 lease、保存/历史写入 workflow、FFmpeg/录屏生命周期。

**动作**：

- 覆盖短暂剪贴板占用、消费者超时、owner HWND 创建失败；
- 覆盖只读目录、临时文件同步失败、目标名冲突、历史索引写入失败；
- 覆盖 FFmpeg 缺失、启动失败、运行中退出和停止超时；
- 让每个失败路径清除 busy 标志、释放 lease/进程/窗口，并保留原选区或可再次 Capture 的入口。

**验收条件**：确定性测试或隔离 Windows 探针能触发每种失败；失败通知能说明下一步动作；随后一次 Capture、
Copy、Save 或 Record 能成功；没有半成品文件、孤儿进程、残留窗口、未释放按键或永久 busy 状态。

**失败处理**：任何资源无法回收时，以有界超时结束并在报告中记录具体资源；该场景标记失败，不能提交为
“恢复完成”。

**当前进度（2026-08-26）**：保存/快速保存的编码、目标目录或文件系统失败现在会把会话从 `Exporting`
恢复到 `Selecting`，保留原选区和标注覆盖层；状态会明确提示选择其他位置后再次 Save。历史索引写入改为
先同步临时文件再替换索引，失败时清理 `.tmp`，新增、清空、删除和后台移除不会提前破坏可重试的
历史状态；相关失败提示已经进入 English/简体中文目录。确定性测试覆盖保存失败恢复和四种历史索引失败
夹具；剪贴板争用、FFmpeg 运行中退出/停止超时以及真实 Windows 失败注入仍待本切片后续完成，不能将
B1 标记为整体完成。

### B2：窗口和任务生命周期

**负责组件**：`overlay.rs`、`pinned.rs`、capture teardown、Pin lifecycle runner。

**动作**：

- 重复执行 Capture、Save -> Pin、Copy -> Close、Escape 取消和再次 Capture；
- 检查 deferred native HWND close 完成前的 `capture_teardown_pending`，不能用 `overlay_count=0`
  代替清理完成；
- 检查 generation、后台任务、快捷键、鼠标键和焦点窗口在取消/关闭后的状态；
- 保持 Pin 的像素源帧不变，窗口关闭后不再有晚到任务写回 UI。

**验收条件**：使用同一 Release 构建运行至少一轮连续场景；报告显示
`capture_teardown_pending=false`、overlay/Pin/控制窗口为零、后台任务结束、输入按键释放，且下一次
Capture 可以完成。

**失败处理**：只要桌面仍有残留、任务未结束或下一次 Capture 被拒绝，就保留报告和步骤截图，回到具体
生命周期分支修复，不扩大到视觉重构。

### B3：历史异步流控

**负责组件**：Library/history reader、缩略图队列和删除/切换目录 workflow。

**动作**：

- 继续保持 300 条请求最多 2 个解码任务、FIFO 顺序和重复渲染去重；
- 在损坏 PNG、文件消失、历史删除、目录切换和窗口关闭时取消或丢弃陈旧结果；
- 将任务归属、队列长度、失败原因和清理结果写入结构化报告。

**验收条件**：单元测试证明队列上限、FIFO、去重和陈旧结果不写回；Release 资源样本记录默认 5 条与
显式 300 条展开的首批缩略图时间、峰值私有字节和结束状态；历史操作不影响截图主链。

**失败处理**：解码失败只影响对应条目，Library 仍能继续浏览、筛选和删除；若任务持续增长或目录归属

