# 主线开发计划

更新日期：2026-10-31
当前源码版本：`0.2.1`，以根目录 `Cargo.toml` 为准。

本文是 Flash Shot 唯一维护的开发计划。只记录当前目标、未完成工作、执行顺序、暂缓项和验收条件。
已完成任务和旧版发布安排不再列入计划；逐次结果查阅 [Windows 手工验收记录](windows-manual-acceptance.md)，旧计划查阅 Git 历史。

本文中的开发切片（Development Slice）是可独立实现、验证和提交的一项结果。原生验收（Native Acceptance）是在真实 Windows 窗口中核验输入、像素、产物和资源清理；静态截图只证明对应的渲染结果。

## 1. 当前目标与边界

Flash Shot 优先支持 Windows。当前主线对照固定 Snow Apps 源码，补齐用户可观察的核心流程。
参考提交固定为 `850d27c113b2f81b43950b839b6180af50e82d13`，来源和更新规则见 [Snow Apps 参考基线](snow-apps-baseline.md)。只有用户明确选定新提交后才更新基准。

当前已具备截图、标注、Copy/Save/Pin/Cancel、Library、Record 视频生命周期和 OCR/二维码主流程；全局 Capture 动作和四页布局已有单屏验收记录。
既有证据主要覆盖单屏 100%、DPI 96。这些结果不代表 Snow Apps 整体能力已对齐，也不代表音频、高 DPI 或多屏矩阵已通过。

后续改动保留选区物理像素、标注文档坐标、快捷键语义、导出格式、历史数据、设置兼容、失败恢复和资源清理规则。
Snow Shot 设置面板仅用于了解必要能力；Flash Shot 继续使用现有简化分组，不复制其设置结构或 Qt/Tauri/Web 架构。

## 2. 未完成工作与顺序

| 编号 | 工作 | 当前状态 | 下一步与完成条件 |
| --- | --- | --- | --- |
| S2 | Record 音频产物与失败恢复 | 进行中 | 增益代码和布局已有证据；补齐真实控件输入、持久化、设备音轨、输入失败和清理验收 |
| S3 | 滚动截图交互 | 待评估 | 在现有垂直拼接基础上，选择有明确收益的扩展；每项独立实现并验收 |
| S4 | Pin、Library 与识别结果扩展 | 待评估 | 按用户优先级选择一项扩展，先确认行为差异和验收条件，再实现 |

执行顺序为 **S2 → S3 → S4**。先完成当前切片，再开始下一项。D1 只有在具备目标显示环境后执行；其他暂缓项按第 4 节恢复条件处理。

### S2：Record 音频产物与失败恢复

已有实现支持 `-24..=24 dB` 增益、单步调整、6 dB 快调和归零，麦克风与系统声音分别保存数值。
旧设置默认 `0 dB`，越界值归入支持范围；未选择音源时收起控件，录制或配置检查期间禁用调整。
已有设置兼容和 FFmpeg 参数测试，以及 English/简体中文、深色/浅色、420/520/980 宽度的 Release 布局截图。
这些证据未覆盖真实鼠标/键盘增益调整、持久化交互或真实设备音轨，S2 保持未完成。

剩余工作与验收条件：

1. 在真实窗口中用鼠标和键盘调整、快调及归零。切换音源、重启应用后回读各自数值；设置写入失败时恢复原值并显示双语错误。
2. 对 Display、Window、Region 分别执行无音频、麦克风、系统声音录制。记录设备、FFmpeg 版本、输入方式和可用条件。
3. 用 FFprobe 核对视频和音轨，并检查声音内容、增益效果及暂停/恢复/停止后的音画连续性。无音频模式不得产生意外音轨。
4. 核验音源不可用、启动失败和录制中断后的错误、重试、输出文件、FFmpeg 进程及临时资源清理。缺少设备或输入支持时，明确保留未验收项。

回滚边界为独立音频切片；保留新增设置字段的兼容默认值，以及既有视频录制和输出行为。

### S3：滚动截图交互

现有手动/辅助垂直采集、重叠拼接、至少两帧限制及 Copy/Save/Cancel 是已有基线，不重复排期。
候选扩展包括水平模式、连续流、自动滚动、实时缩略图和裁剪预览。先评估收益与输入方式，再选择一个独立切片；本计划不承诺一次实现全部候选项。

选中切片须通过真实滚动、追加、停止、预览、Copy/Save/Cancel、失败恢复和窗口排除检查。
拼接结果须有物理尺寸和像素证据；静态拼接测试不能替代交互验收。回滚只移除所选扩展，保留现有垂直主流程。

### S4：Pin、Library 与识别结果扩展

候选范围包括 Pin 原图复制、另存为及文件分组管理，Library 日期筛选、分页及可编辑会话恢复，二维码逐码 URL 操作，以及 Pin 识别结果持久化。
每次对照固定 Snow Apps 提交，说明采用、适配或暂缓的原因；由用户优先级确定具体切片，不自动扩大功能集合。

选中切片须核验真实结果、双语状态、失败重试、持久化兼容和窗口/文件清理。
保留现有 Capture 识别结果的 Copy/Clear/Retry、Pin 多窗口生命周期及 Library 搜索、来源筛选、删除和保留数量行为。
回滚边界为单个扩展及其兼容数据变更。

## 3. 随相关改动执行的验证

- **性能证据**：统一报告的输入/输出边界、提交号、二进制标识、样本数、失败数和清理结果。历史单屏 Copy 已有工具栏与 Enter 各 30 次通过记录；修改对应路径后重新采样，不能沿用旧二进制结论。真实 UI Copy 的 p95 目标为不超过 250 ms。
- **4K 交互**：仍需补齐真实 4K 标注交互的同源测量，p95 帧时间目标为不超过 16.7 ms。其他性能目标见 [产品需求](requirements.md)。
- **失败恢复**：保留 [Windows 手工验收记录](windows-manual-acceptance.md) 中尚未完成的权限、历史索引和设备异常矩阵；相关流程有改动时补齐证据，不把部分通过改写为全部通过。
- **界面回归**：涉及共享布局、主题或本地化时，覆盖 English/简体中文、深色/浅色和 420×420、520×640、980×760；核验滚动、焦点、忙状态和恢复入口。

## 5. 统一验收与提交条件

Rust 源码、Cargo 清单或锁文件有改动时，先确认最新 stable 编译器，并准备仓库要求的 Windows MSVC 环境。
从工作区根目录执行与改动相关的测试和以下检查：

```powershell
rustup run stable rustc -Vv
cargo +stable fmt --all -- --check
cargo +stable check --workspace --all-targets --all-features --locked
cargo +stable clippy --workspace --all-targets --all-features -- -D warnings
cargo +stable test --workspace --all-features --locked
git diff --check
```

Windows 平台或 `dev-tools` 有改动时，还需执行目标检查，并构建用于验收的 Release 程序：

```powershell
cargo +stable check -p flash-shot-app --target x86_64-pc-windows-msvc --all-targets --all-features --locked
cargo +stable build --release -p flash-shot --features dev-tools --locked
```

用户可见改动优先通过 Computer Use 验收真实窗口。不可用时，先做有界启动和窗口恢复检查，再使用仓库现有原生输入 runner 或无界面测试；分别说明证据来源及未覆盖行为。
结构化报告应关联同一源码构建，保存环境、关键截图、实际产物和窗口/进程/任务/输入/临时文件清理结果。外部服务集成测试使用本机 Docker；条件缺失时保持未完成。

纯文档改动检查内容、相对链接、旧引用、UTF-8/LF 和 `git diff --check`；Rust 构建、产品 UI 验收及外部服务集成测试不适用。
每个完成的切片单独提交。验证失败或证据只覆盖部分范围时，保留未完成状态，不提交为已完成功能。
