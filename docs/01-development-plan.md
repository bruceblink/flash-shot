# 主线开发计划

更新日期：2026-11-07
当前源码版本：`0.2.1`，以根目录 `Cargo.toml` 为准。

本文是 Flash Shot 唯一维护的开发计划。只记录当前目标、未完成工作、执行顺序、暂缓项和验收条件。
已完成任务和旧版发布安排不再列入计划；逐次结果查阅 [Windows 手工验收记录](windows-manual-acceptance.md)，旧计划查阅 Git 历史。

本文中的开发切片（Development Slice）是可独立实现、验证和提交的一项结果。原生验收（Native Acceptance）是在真实 Windows 窗口中核验输入、像素、产物和资源清理；静态截图只证明对应的渲染结果。
本轮审查的源码基线为 `2f74c0b7c0de922282a08bd6bf5c4ba68067158a`，问题和证据见 [2026-11-07 代码审查报告](02-code-review-2026-11-07.md)。审查报告保存当次结论，本文维护后续状态。

## 1. 当前目标与边界

Flash Shot 优先支持 Windows。当前主线对照固定 Snow Apps 源码，补齐用户可观察的核心流程。
参考提交固定为 `850d27c113b2f81b43950b839b6180af50e82d13`，来源和更新规则见 [Snow Apps 参考基线](snow-apps-baseline.md)。只有用户明确选定新提交后才更新基准。

当前已具备截图、标注、Copy/Save/Pin/Cancel、Library、Record 视频生命周期和 OCR/二维码主流程；全局 Capture 动作和四页布局已有单屏验收记录。
既有证据主要覆盖单屏 100%、DPI 96。这些结果不代表 Snow Apps 整体能力已对齐，也不代表音频、高 DPI 或多屏矩阵已通过。

2026-11-07 审查确认了历史清理、设置回退、项目文件保存、滚动重叠、子进程管道和录屏生命周期问题。
后续先修复这些问题，再继续音频验收和功能扩展。本次只更新审查与计划文档，没有修复运行时代码。

后续改动保留选区物理像素、标注文档坐标、快捷键语义、导出格式、历史数据、设置兼容、失败恢复和资源清理规则。
Snow Shot 设置面板仅用于了解必要能力；Flash Shot 继续使用现有简化分组，不复制其设置结构或 Qt/Tauri/Web 架构。

| 切片 | 实现范围 | 验收条件 | 回滚边界 |
| --- | --- | --- | --- |
| B1 | 设置加载结果、启动回退和后续写入权限 | 用未来格式、坏 JSON 和读取失败测试启动路径；默认目录分别准备 100/300 条历史，启动后原设置字节、索引与图片不变；明确提示恢复方式；首次运行仍可使用默认值 | 只调整启动与设置恢复；不改已有字段、历史目录归属或文件格式 |
| B2 | `ScreenshotHistory::load` 的索引提交与超限删除顺序 | 用两条历史、上限 1 和索引临时路径冲突复现；失败后旧图与原索引不变；恢复条件后能重试；删除失败可见、可恢复 | 只调整历史加载和清理顺序；不扩大删除目录，不扫描接管未登记文件 |

### B4～B5：输出内容与子进程正确性

**B4：滚动拼接。** 先加入白底、稀疏文字和重复背景的确定性回归。
最小复现为两张 `1×100` 帧，实际滚动 20 像素，页面第 50/110 行为黑色。
结果须为 `1×120`，两行内容都保留；无法判断的帧须返回可重试错误。
同时保留现有高对比度、未滚动、无可靠重叠及多帧拼接测试。
随后用真实白底页面核验滚动、追加、停止、Copy/Save/Cancel 和像素完整性。
回滚只调整重叠判断与拒绝反馈，保留手动/辅助垂直主流程，不顺带增加水平或自动滚动能力。

**B5：OCR 与 FFmpeg 探测。** 两个执行入口分别验证，可分别提交，不因代码相似提前创建通用进程框架。
用测试子进程分别写满 stdout、stderr 和双管道，验证正常结果不因管道容量超时。
另测真实不退出、非零退出、读取失败及取消后的进程回收，并规定输出保留上限。
保留 OCR 20 秒、FFmpeg 探测 10 秒的有界等待语义；只替换输出读取与清理流程。
探测测试不启动屏幕或音频采集。修复后再运行可用 Tesseract/FFmpeg 的实际只读支持检查；缺少工具时保留未验收状态。

### B6～B7：录屏终止与退出

**B6：退出收尾。** 先定义退出时保留完成录屏还是放弃本次录屏。
退出流程必须等待工作线程报告产物或清理结果，并设置明确期限；超时后终止进程并按约定处置本次 `.part-…mp4`。
用无设备测试子进程覆盖等待和清理，再在真实录制、暂停、启动中、停止中分别退出。
核验最终文件可播放或被明确放弃，且 FFmpeg、读取线程和临时文件无残留。
回滚限于退出协调和工作线程完成通知，不改变普通 Stop 的产物规则。

**B7：终止状态。** 用容量已满的事件队列分别触发成功、失败和接收端关闭。
确认用户最终能观察到结束或失败，界面和托盘回到可重试状态。
允许进度合并或丢弃；终止状态不能因进度拥塞丢失。
保持内存有界，不增加无界通道。回滚限于事件送达与接收结束处理，不重写录屏状态机。

B6/B7 修复后重新运行已有 Record 启动失败、重试、暂停、恢复、停止的 Release 验收。
这不代表麦克风或系统音轨已验收；音频证据仍在 S2 收集。

### Q1：工具链与测试执行边界

1. 对齐本地、质量 CI 和 Release 的 stable/MSVC 基线；增加 `rust-toolchain.toml`，将 workspace `rust-version` 与实际 stable 编译器对齐。发布前记录编译器版本、宿主与目标架构。
2. check、严格 Clippy 和测试编译覆盖 `--all-features`、`--locked`。不把默认 features 的成功视为 `dev-tools` 已验证。
3. 把真实屏幕采集和系统热键注册与普通测试分开，复用已有开发工具或显式桌面测试入口。默认测试不得隐式读取用户桌面、改剪贴板或占用系统热键。
4. CI 明确 Windows runner 版本、架构、超时、权限、取消旧质量检查和缓存输入。保留质量检查与发布打包分离；当前只交付 Windows，不顺带增加跨平台范围。

验收：无交互桌面的普通测试通过；隔离交互桌面的显式测试报告实际采集、快捷键注册及释放结果；
默认与 `dev-tools` 的构建均通过。发布脚本的打包和校验测试仍需通过，但不发布 Release、不监测 CI，除非另有发布任务或用户要求。
回滚限于工具链与检查配置，不降低现有 lint，不取消必要的原生验收。

### S2：Record 音频产物与失败恢复

已有实现支持 `-24..=24 dB` 增益、单步调整、6 dB 快调和归零，麦克风与系统声音分别保存数值。
旧设置默认 `0 dB`，越界值归入支持范围；未选择音源时收起控件，录制或配置检查期间禁用调整。
已有设置兼容和 FFmpeg 参数测试，以及 English/简体中文、深色/浅色、420/520/980 宽度的 Release 布局截图。
这些证据未覆盖真实鼠标/键盘增益调整、持久化交互或真实设备音轨，S2 保持未完成。

剩余工作与验收条件：

1. 在真实窗口中用鼠标和键盘调整、快调及归零。切换音源、重启应用后回读各自数值；设置写入失败时恢复原值并显示双语错误。
2. 对 Display、Window、Region 分别执行无音频、麦克风、系统声音录制。记录设备、FFmpeg 版本、输入方式和可用条件。
3. 用 FFprobe 核对视频和音轨，并检查声音内容、增益效果及暂停/恢复/停止后的音画连续性。无音频模式不得产生意外音轨。
4. 核验音源不可用、启动失败和录制中断后的错误、重试、输出文件、FFmpeg 进程及临时资源清理。缺少设备或输入支持时，明确保留未验收项。

回滚边界为独立音频切片；保留新增设置字段的兼容默认值，以及既有视频录制和输出行为。

### S3：滚动截图交互

现有手动/辅助垂直采集、单次滚轮后延时自动采集、重叠拼接、至少两帧限制及 Copy/Save/Cancel 是已有基线，不重复排期。B4 单独处理现有重叠算法的问题。
候选扩展包括水平模式、连续采集、无需逐次触发的自动滚动、实时缩略图和裁剪预览。先评估收益与输入方式，再选择一个独立切片；本计划不承诺一次实现全部候选项。

选中切片须通过真实滚动、追加、停止、预览、Copy/Save/Cancel、失败恢复和窗口排除检查。
拼接结果须有物理尺寸和像素证据；静态拼接测试不能替代交互验收。回滚只移除所选扩展，保留现有垂直主流程。

### S4：Pin、Library 与识别结果扩展

现有 Pin Copy 使用保留的合成图片，不受窗口缩放和透明度影响；快速保存也已实现。这些能力不重复排期。
候选范围包括 Pin 未标注源图复制（不同于现有合成图片 Copy）、另存为及文件分组管理，Library 日期筛选、分页及可编辑会话恢复，二维码逐码 URL 操作，以及 Pin 识别结果持久化。
每次对照固定 Snow Apps 提交，说明采用、适配或暂缓的原因；由用户优先级确定具体切片，不自动扩大功能集合。

选中切片须核验真实结果、双语状态、失败重试、持久化兼容和窗口/文件清理。
保留现有 Capture 识别结果的 Copy/Clear/Retry、Pin 多窗口生命周期及 Library 搜索、来源筛选、删除和保留数量行为。
回滚边界为单个扩展及其兼容数据变更。

## 3. 随相关改动执行的验证

- **性能证据**：统一报告的输入/输出边界、提交号、二进制标识、样本数、失败数和清理结果。历史单屏 Copy 已有工具栏与 Enter 各 30 次通过记录；修改对应路径后重新采样，不能沿用旧二进制结论。真实 UI Copy 的 p95 目标为不超过 250 ms。
- **4K 交互**：仍需补齐真实 4K 标注交互的同源测量，p95 帧时间目标为不超过 16.7 ms。其他性能目标见 [产品需求](requirements.md)。
- **失败恢复**：保留 [Windows 手工验收记录](windows-manual-acceptance.md) 中尚未完成的权限、历史索引和设备异常矩阵；相关流程有改动时补齐证据，不把部分通过改写为全部通过。
- **界面回归**：涉及共享布局、主题或本地化时，覆盖 English/简体中文、深色/浅色和 420×420、520×640、980×760；核验滚动、焦点、忙状态和恢复入口。

## 5. 统一验收与提交条件

Rust 源码、Cargo 清单或锁文件有改动时，先确认最新 stable 编译器，并准备仓库要求的 Windows MSVC 环境。
本轮验证使用的本机 stable 为 `rustc 1.99.1`、`x86_64-pc-windows-msvc`；后续执行时重新核验，不能把该版本号当作永久固定值。
在同一 PowerShell 进程初始化 MSVC/CMake 环境后，从工作区根目录执行与改动相关的测试和以下检查：

```powershell
rustup run stable rustc -Vv
cargo +stable fmt --all -- --check
cargo +stable check --workspace --all-targets --all-features --locked
cargo +stable clippy --workspace --all-targets --all-features --locked -- -D warnings
cargo +stable test --locked -p flash-shot-domain -p flash-shot-image --all-features
git diff --check
```

以上领域库和图像库测试只是普通测试的已知安全子集，不代替修改过的应用模块测试。
应用模块先检查测试是否会访问真实系统，再执行对应的确定性测试。
Q1 完成前，下面的全工作区测试会包含真实桌面采集和热键注册，只能在明确准备的隔离桌面运行；本轮审查没有执行：

```powershell
cargo +stable test --workspace --all-features --locked
```

Q1 完成后，普通工作区测试与真实桌面验收分别记录结果。任一部分未执行时不得写成完整验收通过。

Windows 平台或 `dev-tools` 有改动时，还需执行目标检查，并构建用于验收的 Release 程序：

```powershell
cargo +stable check -p flash-shot-app --target x86_64-pc-windows-msvc --all-targets --all-features --locked
cargo +stable build --release -p flash-shot --features dev-tools --locked
```

用户可见改动优先通过 Computer Use 验收真实窗口。不可用时，先做有界启动和窗口恢复检查，再使用仓库现有原生输入 runner 或无界面测试；分别说明证据来源及未覆盖行为。
结构化报告应关联同一源码构建，保存环境、关键截图、实际产物和窗口/进程/任务/输入/临时文件清理结果。外部服务集成测试使用本机 Docker；条件缺失时保持未完成。

纯文档改动检查内容、相对链接、旧引用、UTF-8/LF 和 `git diff --check`；Rust 构建、产品 UI 验收及外部服务集成测试不适用。
每个完成的切片单独提交。验证失败或证据只覆盖部分范围时，保留未完成状态，不提交为已完成功能。
