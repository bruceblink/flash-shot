# Snow Shot 对齐开发计划

## 1. 目标

Flash Shot 以 Snow Shot 的高频桌面工作流为产品基线，在保留 Rust/GPUI 原生架构的
前提下，达到以下结果：

1. 截图、编辑、复制、保存、Pin 和历史复用路径稳定且符合直觉。
2. 主界面、截图覆盖层和独立工具窗口使用一致的视觉语言与交互反馈。
3. Snow Shot 中高价值、低依赖的效率能力有明确的实现或取舍。
4. Windows 实机行为、性能和资源生命周期能够被重复验证。

对齐指任务完成效率和交互清晰度，不复制 Snow Shot 的 Tauri、WebView、React、
Excalidraw 或插件实现。

## 2. 参考基线

产品基线来自 Snow Shot 官方资料：

- 官方仓库：https://github.com/mg-chao/snow-shot
- 官方功能说明：https://snowshot.top/
- 官方快速入门：https://snowshot.top/guide/

重点参考的已验证模式包括智能窗口识别、选后标注、稳定的主操作、可移动和缩放的多
Pin、截图历史、快捷入口、主题配色，以及按需加载 OCR、翻译和录屏等高级能力。

## 3. 当前状态与差距

截至 2026-07-29，Flash Shot 已实现区域与智能选区、多显示器、标注、复制与保存、
Pin、截图历史、二维码、可选 OCR/翻译、滚动截图和 FFmpeg 录屏。核心自动测试为
293 项，严格 Clippy 当前通过。

| 领域 | 当前状态 | 与 Snow Shot 的主要差距 | 优先级 |
| --- | --- | --- | --- |
| 稳定性 | 有显式截图/录屏状态和后台任务 generation | Windows 独立窗口和真实多屏仍缺完整运行态审查 | P0 |
| 截图覆盖层 | 智能目标、自由选区、放大镜和主次工具栏已具备 | 窄选区密度、动作排序和混合 DPI 实机一致性需复核 | P0 |
| 标注 | 主要工具、样式、图层、文字和撤销重做已具备 | 控件密度、选中反馈和连续编辑效率仍需统一 | P1 |
| Pin | 多 Pin、置顶、复制、保存、透明度和穿透已具备 | 应改为图片优先的悬浮控制，并恢复无边框自由调整大小 | P0 |
| 历史 | 缩略图、相对时间、展开和单项动作已具备 | 缺少搜索、筛选和更高效的批量管理 | P1 |
| 设置主页 | 分组页面、深浅主题和状态反馈已具备 | 信息架构偏工程面板，快捷功能与设置入口不够清晰 | P1 |
| 保存 | PNG、快速保存和项目 sidecar 已具备 | 缺少多格式导出和可见的默认路径/命名配置 | P2 |
| 高级能力 | OCR、翻译、滚动截图和录屏已具备 | 环境检查、失败恢复和入口一致性需实机验收 | P2 |

## 4. 实施阶段

### 阶段 0：审查基线与计划

- [x] 建立 Snow Shot 官方功能与交互基线。
- [x] 梳理 Flash Shot 当前功能、测试和主要差距。
- [x] 规定分阶段验收与提交规则。
- [ ] 建立 Windows 手工验收记录，覆盖单屏、负坐标双屏和混合 DPI 双屏。

退出标准：后续每项改动都能对应到本计划中的差距和验收项。

### 阶段 1：完整代码审查与已知问题修复

1. 对截图、Pin、历史、滚动截图、录屏和应用退出的异步状态进行逐路径审查。
2. 审查 Windows HWND、剪贴板、托盘、快捷键、进程和临时文件的所有权与清理。
3. 修复 UI 线程阻塞、晚到任务覆盖新状态、窗口重入、无界缓存和错误吞没。
4. 运行格式化、严格 Clippy、全量测试和差异检查。

退出标准：

- cargo fmt --check 通过。
- cargo clippy --all-targets --all-features -- -D warnings 通过。
- cargo test 全部通过。
- 已发现的 P0/P1 正确性问题均有回归测试或明确的 Windows 验收步骤。

### 阶段 2：核心截图与标注交互

1. 保持复制、保存、Pin 和取消为稳定主动作，低频功能渐进展开。
2. 验证智能窗口单击采用、自由拖动、选区移动/缩放和键盘微调的优先级。
3. 统一标注工具的选中、悬停、禁用、样式面板和撤销重做反馈。
4. 在窄选区、屏幕边缘和跨屏选区中避免工具栏遮挡或跳动。

退出标准：区域截图从唤起到导出的完整路径无需打开设置窗口；单屏和多屏只出现一组
可操作工具栏；像素尺寸和导出结果保持物理像素正确。

### 阶段 3：Pin、历史和快捷入口

1. Pin 采用图片优先的无边框界面，控制条仅在悬停或明确操作时出现。
2. Pin 支持自由移动、等比缩放、透明度、复制、保存、关闭和多窗口管理。
3. 历史支持搜索、快速预览、打开、复制、Pin、删除和清空确认。
4. 托盘、主页和全局快捷键对同一动作使用一致命名与状态反馈。

退出标准：多张 Pin 可独立操作且不阻塞主应用；Pin 初始图片显示尺寸与选区一致；
300 条历史记录下默认打开仍保持轻量。

### 阶段 4：主界面与视觉系统

1. 将主页调整为高频功能入口，设置项按界面、功能、热键、系统分组。
2. 统一颜色语义、排版层级、行高、间距、边框、圆角和焦点状态。
3. 用图标承载熟悉动作，文本用于明确命令；所有非直观图标提供 tooltip。
4. 完善加载、空状态、成功、失败、确认和不可用状态。
5. 验证最小窗口、100%/150%/200% 缩放和深浅主题。

退出标准：主要页面不存在文本截断、控件跳动、重叠或嵌套卡片；同类控件拥有一致
尺寸和反馈；键盘焦点清晰可见。

### 阶段 5：关键能力差距

按价值和风险依次评估并实现：

1. 历史关键词搜索与筛选。
2. PNG 之外的 JPG/WebP 导出，以及默认目录和命名配置。
3. 焦点窗口截图与更直接的窗口截图入口。
4. 可配置的多动作全局快捷键。
5. 自动滚动截图和高级 OCR/翻译失败恢复。

插件市场、AI 对话和在线协作不进入核心链路；只有在截图主流程、性能和稳定性完成
验收后再单独立项。

### 阶段 6：最终验收

自动验证：

- 全量测试、严格 Clippy、格式检查和 git diff --check。
- 100 次连续截图资源与延迟测试。
- 4K 标注压力测试和性能报告。

Windows 实机矩阵：

- 单显示器 100%。
- 负坐标双显示器。
- 混合 DPI 双显示器。
- 最小设置窗口和窄选区。
- 多 Pin 的移动、缩放、复制、保存、透明度、关闭和主应用继续截图。
- FFmpeg 可用环境下的显示器、窗口、区域录屏及暂停/恢复/停止。

最终退出标准：逐项复核本计划的显式要求，所有 P0/P1 差距均有当前代码、自动测试或
实机记录证明完成；未完成的 P2 项必须有明确取舍，不能以“未发现问题”代替验收。

## 5. 提交与验证规则

- 每个有边界的修复或功能单独提交，提交信息沿用 Conventional Commits。
- 不提交验证失败或仅完成一半的功能。
- 先修正确性和交互，再做纯视觉调整。
- 新增交互优先抽取可测试逻辑，Windows 原生行为必须补充手工验收记录。
- 不因对齐 Snow Shot 引入 WebView 或让可选能力拖慢快捷键到覆盖层的主路径。
